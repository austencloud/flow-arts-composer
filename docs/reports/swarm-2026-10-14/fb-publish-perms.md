## Item A: publish trace

**Observation:** `src/lib/shared/sequence-viewer/state/library-action-handler.svelte.ts:handlePublishAction` requires an owned library record and calls `LibraryRepository.publishSequence`. `src/lib/features/browse/shared/services/browse-event-handler.ts:handlePublish` calls the same method. Neither UI handler writes Firestore. The viewer catches with a generic toast; Browse displays the thrown message. Reportable diagnostics originate below them.

`src/lib/shared/library/services/library-repository.ts:publishSequence` captures the owner, reads the source, and either changes visibility through `updateSequence` or repairs an already-public mirror. The visibility write precedes the public transaction. `src/lib/features/library/services/public-index-syncer.ts:syncToPublicIndex` normalizes, moderates, reads profile/tags/optional LOOP labels, computes hashes, then calls `publishPublicSequence`. After publication the repository touches referenced collections. A failed public transaction can therefore leave the owner document marked public; retrying runs the mirror repair.

### Ranked causes

1. **Inference, leading hypothesis, low confidence for this incident:** an existing profile outside the v2 public contract fails the unconditional publisher-profile read inside the exact `Couldn't publish your sequence` catch. `git log -1 -S 'function isSafePublicProfile' -- firestore.rules` returned `fe7e5ce604`, 2026-08-01, `feat(profiles): migrate public user profiles to v2 schema with custom-claim privileges`, before the report date. Susie's actual profile/deployment was not inspected.
2. **Inference, low confidence:** cached old client writes a pre-schema-2 projection, or a legacy mirror/claim conflicts with the source identity. Current rules explicitly reject the old shape. A different-sequence claim normally gives `PUBLIC_DUPLICATE`; same-sequence/wrong-owner claims can instead deny the commit. No claim was inspected.
3. **Inference, low confidence:** auth uid/provider changed during awaits or differs from the selected effective user. Current code has owner fences, but no token evidence establishes the incident state. `isFullUser` (rules lines 17–20) checks provider != anonymous, not paid tier, email verification, displayName, or photo.
4. **Inference, weaker fit for this title:** tag read or post-publish collection refresh. Tags require captured owner identity; collections missing `isPublic` can deny. Collection refresh uses a different report message and runs after successful sync.
5. **Observation with incident relevance unproven:** flagged-word appeal query lacks an owner constraint. Before this patch it ran outside the generic syncer catch, making it a weak fit for the supplied title. **Proposal:** scope the query to the caller or use a deliberately public/server-owned whitelist contract. Do not loosen appeals read rules to expose others' data. No adjacent moderation behavior change made.
