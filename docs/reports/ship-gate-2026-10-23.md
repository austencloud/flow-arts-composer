## The publish preflight

- `scripts/ci-replica.mjs` runs the `validate` steps in order, reading them
  from `web-ci.yml` (`scripts/lib/ci-steps.mjs`) so the list cannot drift. It
  stops at the first red step like CI; `--keep-going` runs them all. Each step
  prints a timed `=== RESULT` line and the run ends with `=== SUMMARY`.
- `scripts/push-public.mjs --push` now runs the replica on d2 against the
  exact snapshot it is about to push, and refuses on red, naming the failing
  step. `--check` runs the same preflight without pushing. A green tree is
  remembered in `.git/publish-preflight-green.txt`, so a `--push` after a green
  `--check` does not run the 17-minute replica again. If d2 does not answer
  ssh it refuses and names `--push --skip-preflight`, which publishes unchecked
  with a warning. (Folded in on 2026-10-27 with Austen's yes; the first
  version wrapped the script from a separate `publish-preflight.mjs`.)
- Dry run on a deliberately red commit (`7e3e6f1822`, the branch with one
  spec's header removed, never on any branch): snapshot `7ba16c5858`, d2
  install 1.5 min, then "Refusing: snapshot 7ba16c5858 is red on d2. Failing
  step: Validate active spec queue." exit 1.

## Why bad commits reach main: local gate versus CI

Update 2026-10-27: main's `70501e8407` (2026-10-25) now makes `wt:finish`
run `check:tsc`, `specs:check`, `specs:test` and the touched tests, and runs
the spec checks on documentation-only merges too. That is recommendation (a)
below plus the touched tests. The rest of this section is the 10-23 finding.

`wt:finish` (`scripts/worktree-automerge.mjs:315-338`) runs `npm run check`
(svelte-check) and `svelte-compile-gate.mjs` on changed components. It never
runs `check:tsc`, `specs:check` or Vitest, and it skips every check when a
branch changes only documentation. svelte-check has dropped project files
since 2026-08-01 (`scripts/tsc-gate.mjs:7-15`) and finished "0 errors" in 19 s
on a commit plain tsc rejects. Every red step of 10-22 and tonight belongs to
a check `wt:finish` does not run.

## Recommendation for wt:finish (not changed tonight)

Six distinct red causes were seen between 10-22 and tonight: two plain-tsc
errors, one spec header gap, and three Vitest failures (one i18n test, two
source-reading contract tests). The two contract tests read source files as
text, so `vitest related` on the changed files would not have run them.

- **(a, recommended)** `wt:finish` adds the cheap CI steps locally on every
  merge: `specs:check` (also on docs-only merges) and `check:tsc` on code
  merges, about 2.5 min on d1. Plus one d2 replica of local main after each
  overnight wave or before each publish (the preflight already does the
  latter). Catches the tsc and spec causes at merge time; Vitest causes surface
  within one replica run instead of at a failed deploy.
- (b) `wt:finish` runs the full replica on d2 for each merge, with a loud local
  fallback (`check:tsc` + `specs:check`) when d2 is down. Catches all six, but
  adds about 25 min per merge and queues on d2 during busy nights.
- (c) Leave `wt:finish` alone and rely on the publish preflight only. Red
  commits keep landing on main and surface at publish time.
